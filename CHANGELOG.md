# История изменений / Changelog

Все значимые изменения в проекте ZealousMindedPeopleGeo документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/),
и проект придерживается [Semantic Versioning](https://semver.org/lang/ru/).

## [Unreleased] - 2024-12-XX

### Документация
- **Документация разделена по темам и по языкам.** README стал коротким: что входит в библиотеку, быстрый старт и ссылки. Остальное перенесено в `docs/`: отдельно разделы для приложения на C# / Blazor (встраивание, компоненты, гео-данные, хранилище, конфигурация, сервисы и ошибки, язык, PWA), отдельно JavaScript в браузере (`docs/javascript.md`) и разработка библиотеки (`docs/development.md`). В разработке теперь явно сказано, что Node.js нужен только для тестов JavaScript, а тесты C# (`dotnet test`) и тесты JavaScript (`node --test`) описаны в разных разделах
- **Подключение без NuGet.** Документация предлагала `dotnet add package ZealousMindedPeopleGeo`, хотя в NuGet библиотека не публикуется. Теперь описано подключение ссылкой на проект (подмодуль git и `dotnet add reference`). Отдельно сказано, что библиотека должна лежать рядом с проектом приложения, а не в его папке: иначе SDK приложения захватывает тесты и витрину библиотеки и сборка падает. Значок NuGet убран
- Описание `IThreeJsGlobeService` приведено к настоящему интерфейсу; повторяющиеся разделы «Архитектура», «Множественные глобусы» и «Использование в Blazor проектах» объединены

### Удалено
- **Встроенное постоянное хранение.** Библиотека даёт интерфейсы хранилищ (`IGeoDataContainerManager`/`IGeoDataContainer`, `IParticipantRepository`) и реализации в памяти. Постоянное хранение реализует приложение (см. README, «Своё хранилище»). Удалены:
  - хранение контейнеров в базе через EF Core: `AddGeoDataDatabase`, `EnsureGeoDataDatabaseCreatedAsync`, `DatabaseGeoDataContainerManager`, `GeoDataDbContext`, `GeoDataDatabaseInitializer`, пример `examples/GeoDataDatabaseExample.razor`;
  - участники в Google Sheets: `GoogleSheetsParticipantRepository`, `GoogleSheetsService`, `IParticipantService`/`ParticipantService`, `InitializeZealousMindedPeopleGeoAsync`, настройки `GoogleSheetId` и `GoogleServiceAccountKey`, класс `RegistrationResult`;
  - зависимости от пакетов `Microsoft.EntityFrameworkCore`, `Microsoft.EntityFrameworkCore.Relational` и `Google.Apis.Sheets.v4`.

  Ключи `GoogleSheetId` и `GoogleServiceAccountKey` в `appsettings.json` теперь просто игнорируются. Код, который вызывал удалённые методы, нужно перевести на свою реализацию интерфейса

- **Неработающие и неиспользуемые части:**
  - `ValidationService`, `LocalizationService` и валидаторы FluentValidation (`ParticipantValidator` и др.) вместе с зависимостью от пакета FluentValidation. `ValidationService` не регистрировался, поэтому пример из README не работал; ввод формы проверяют атрибуты моделей, точки — `GeoPoint.Validate()`
  - `IMapService` и `GoogleMapsServiceAdapter` — регистрировались, но ими никто не пользовался
  - `IGeoJsonService`, `FileGeoJsonService` и прежняя модель GeoJSON (`GeoJsonFeatureCollection` и др.). Для GeoJSON есть `GeoPointGeoJson`
  - Правила сервис-воркера для `/api/participants`, `/api/geocoding`, `/api/healthcheck`: такие запросы и так шли по Network First
  - CSS для класса `.participant-registration`, которого нет ни в одном компоненте
  - Скриншоты `docs/screenshots`, HTML-черновики в `experiments/` и `examples/`, проект `experiments/data-isolation-test` (его проверки покрывают тесты контейнеров и демо-наборов)

- **Код, которым никто не пользовался:** папка `Interfaces/` (`IDataSource`, `IDataSourceManager`, `IGeocodingServiceSimple` и их модели — набросок, у которого не было ни одной реализации), классы `GlobePointData`, `PointAnimation`, `GlobeCountryData`, `GlobeEvent`, `GlobePerformanceConfig`, три `.bak`-файла, `js/test-globe.js`, `js/globe-initializer.js` и `js/libs/three.core.min.js` (глобус грузит `three.core.js`)

- **Настройки, которые ничего не делали:** `EnableParticipantValidation`, `EnableRateLimiting`, `MaxParticipantsPerHour`, `DefaultCulture` и `Map:MapTheme`. Библиотека их не читала, а `EnableRateLimiting = true` создавал впечатление встроенной защиты. Ограничения — задача приложения (см. `OnSubmitting`), язык сообщений берётся из `CurrentUICulture`. Эти ключи в `appsettings.json` просто игнорируются; код, который их присваивает, надо поправить

- **Устранены дубликаты функциональности (Issue #4)**
  - Удален компонент `ParticipantRegistrationComponent.razor` - заменен на более продвинутый `GeoDataParticipantForm.razor`
  - Удалено дублирующееся поле `Timestamp` из модели `Participant.cs` - используется `RegisteredAt`
  - Мигрированы все ссылки на `Timestamp` на `RegisteredAt` в:
    - `GoogleSheetsService.cs`
    - `community-map.js`
    - `GeoJson.cs`

- **Отладочный вывод:** статический `GlobeMediatorService.OnGlobeReady` — его не вызывал ни один скрипт, он только печатал в консоль (готовность глобуса передаёт `SetReadyCallbackAsync`)

### Добавлено
- **Своя планета на 3D-глобусе.** `CommunityGlobeViewer.Planet` (и `CommunityGlobeComponent.Planet`, `GlobeOptions.Planet`, опция `planet` JS-глобуса) показывает вместо Земли любую планету по `GlobePlanet`: карта поверхности обязательна, рельеф, шероховатость, облака, огни ночной стороны и цвет атмосферы — по желанию. От Земли ничего не подмешивается, её текстуры не загружаются. На витрине на странице `/globe` переключатель «Планета» с выдуманной планетой (карта сгенерирована шумом на сфере)
- **День и ночь на 3D-глобусе (по желанию).** `CommunityGlobeViewer.DayNightMode = GlobeDayNightMode.RealTime`: солнце там, где оно сейчас (или в `DayNightTime`). Ночная сторона тёмная, с огнями городов, атмосфера над ней гаснет, граница сдвигается сама. Карта ночных огней грузится только в этом режиме. Галочка «День и ночь» есть в `CommunityGlobeSettings`, переключатель освещения — на странице глобуса в витрине
- **Глобус открывается на своих точках.** При первой загрузке он поворачивается к среднему направлению на точки (широта не больше ±60°), если пользователь ещё не крутил его сам. Туда же возвращает Home. Точки, разбросанные по всему миру, оставляют вид по умолчанию
- **Поиск адреса без ключа Google.** Без `GoogleMapsApiKey` адреса для формы ищет Nominatim (OpenStreetMap): бесплатно, на языке пользователя, не чаще запроса в секунду к серверу, с кэшем на сутки и подписью источника под найденным адресом (`GeocodingResult.Attribution`). Свой сервер задаётся в `NominatimUrl`. С ключом, как и раньше, ищет Google. `NominatimGeocodingService` умеет и обратный поиск (координаты → адрес)
- **Понятные сообщения об ошибках глобуса и геокодирования.** `GlobeInitializationResult.Error` (`GlobeInitializationError`: `WebGlUnavailable`, `ScriptsUnavailable`, `ContainerNotFound`, `Unknown`) и `GeocodingResult.Error` (`GeocodingError`: `NotFound`, `Unavailable`, `Failed`). Компоненты показывают по ним текст на языке пользователя. Технический текст остаётся в `ErrorMessage` и в журнале. Без WebGL глобус объясняет, что делать, и не предлагает «Повторить», потому что повтор не поможет. Если не удалось показать точки, «Повторить» загружает их заново и не перезапускает глобус
- **Витрина на двух языках.** Все надписи тестовой среды (меню, страницы, сообщения об импорте GeoJSON, 404) переведены на английский и лежат в `Site.resx`/`Site.ru.resx` хоста. В меню появился переключатель RU / EN, `<html lang>` следует за языком. Названия и описания демо-наборов (`DemoDataSets.All`) тоже на языке пользователя; сами точки наборов не переводятся

- **Глобус и карта на телефоне.** Быстрый вертикальный взмах по глобусу прокручивает страницу с инерцией, медленное движение и взмах вбок вращают глобус. Щипок приближает поверхность пропорционально движению пальцев, а не проскакивает к земле. Подписи на маленьком холсте мельче (34 px на холсте высотой 600 px, не мельче 15 px), подпись, которая не помещается в холст, не показывается. На узком экране 2D-карта по высоте подстраивается под ширину (без пустой полосы), кнопки легенды и «Точки» на сенсорных экранах не ниже 44 px. В витрине шапка на телефоне переносится на вторую строку, длинный заголовок «Все компоненты» больше не сдвигает страницу вбок

- **Управление 3D-глобусом с клавиатуры.** Холст глобуса доступен по Tab: стрелки поворачивают глобус, `+` и `−` меняют масштаб, Home возвращает начальный вид, N и P перебирают видимые маркеры, Enter подлетает к точке или приближает к группе, Esc снимает выбор. Выбранный маркер обведён кольцом, экранный диктор зачитывает его название; пока глобус в фокусе, он не вращается сам. Подпись холста и подсказка про клавиши — на языке пользователя (`GlobeOptions.Texts`, `GlobeOptions.Locale`)

- **Группы близких точек на 3D-глобусе**, как на 2D-карте: близкие маркеры сливаются в один с числом точек и самым частым цветом. Группы пересобираются при приближении и отдалении (вращение их не трогает), вплотную к поверхности видны все точки. Клик по группе подводит к ней камеру. Параметры `ClusterPoints` и `ClusterRadius` у `CommunityGlobeViewer` и `CommunityGlobeComponent`, опции `clusterPoints`/`clusterRadius` у JS-глобуса

- **Синхронизация между серверами через `IGeoDataChangeBus`.** Если приложение работает на нескольких серверах с общим хранилищем, оно регистрирует свою шину (Redis pub/sub, SignalR backplane, очередь). Менеджер контейнеров отправляет в неё каждое изменение и передаёт подписчикам `OnDataChanged` изменения с других серверов, свои сообщения не повторяет. Без шины синхронизация работает в пределах одного сервера, как раньше. Пример на Redis — в README

- **Синхронизация глобуса между пользователями** (issue #57). `CommunityGlobeViewer` с `DataContainerId` перерисовывается сам, как только контейнер изменился: у всех, кто открыл страницу, без опроса по таймеру. 2D-карта так уже умела. Панель `CommunityGlobeParticipantManager` получила `DataContainerId` и пишет точки в контейнер (`CommunityGlobeComponent` передаёт его сам). Идея и часть решения — из PR #58 (@konard)

- **Управление 2D-картой с клавиатуры.** Холст карты стал доступен по Tab. Стрелки двигают карту, `+` и `−` меняют масштаб, Home возвращает начальный вид. N и P перебирают видимые маркеры, Enter открывает точку или раскрывает группу, Esc снимает выбор. Выбранный маркер обведён кольцом и сопровождается подсказкой, экранный диктор зачитывает его название. Подсказка про клавиши (`aria-describedby`) показывается на языке пользователя

- **Глобус, PWA-менеджер и витрина на языке пользователя.** `CommunityGlobeViewer`, `CommunityGlobeControls`, `CommunityGlobeParticipantManager`, `CommunityGlobeSettings`, `PwaManagerComponent` и `LibraryShowcaseComponent` берут надписи из `Resources/Ui.resx` по `CurrentUICulture`; вопрос «обновить приложение?» сервис-воркера `PwaService` передаёт в `pwa.js` на том же языке. Кнопка вращения глобуса получила подпись для экранного диктора

- **Форма участника и 2D-карта на языке пользователя.** Надписи `GeoDataParticipantForm` и `CommunityMapComponent`, сообщения проверки полей участника и надписи внутри карты (кнопки масштаба, подсказки, «5 точек» с формами числа по `Intl.PluralRules`) — по `CurrentUICulture`, английский и русский. Тексты — в `Resources/Ui.resx` и `Ui.ru.resx`. Раньше карта говорила по-русски, форма — по-английски, а её ошибки — по-русски. Без Blazor надписи карты английские; свои передаются в `initializeCommunityMap(..., { locale, texts })`

- **Проверка на GitHub Actions.** На каждый PR и push в `master` собирается решение и запускаются .NET-тесты (дважды: с обычной и русской локалью) и JS-тесты

- **Проверка приложения перед сохранением в форме.** `GeoDataParticipantForm.OnSubmitting` получает готового участника перед сохранением: `null` — сохранить, строка — отказать с этим сообщением. Так приложение подключает вход, капчу или ограничение частоты; сама библиотека добавление точек не ограничивает

- **Щипок на 2D-карте.** Двумя пальцами карту можно приближать и двигать: место между пальцами остаётся под ними, а оставшийся палец продолжает перетаскивание без скачка. Страница при этом не масштабируется. Щипок на тачпаде ноутбука (браузер шлёт его как колесо с Ctrl) следует за пальцами, а не прыгает на ×1,25 за каждое событие. Касание маркера по-прежнему открывает карточку, а после щипка карточка не открывается

- **Сообщения на языке пользователя.** Причины пропуска при импорте GeoJSON, ошибки `GeoPoint.Validate()` и `JsonException` из `GeoPointGeoJson.Read`, ошибки загрузки JSON в менеджере контейнеров и отказ для участника без координат выходят на языке `CultureInfo.CurrentUICulture`: английский (он же для языков без перевода) и русский. Тексты лежат в `Resources/Messages.resx` и `Messages.ru.resx`; новый язык — ещё один такой файл. Витрина выбирает язык по браузеру (русский по умолчанию, `?ui-culture=en` — явно)

- **Импорт и экспорт GeoJSON**
  - `GeoPointGeoJson.Write` и `GeoPointGeoJson.Read`: точки ↔ `FeatureCollection` по RFC 7946. Поля точки лежат в `properties` под именами `title`, `description`, `category`, `marker-color`, `icon`, `url` (заголовок, описание и цвет — по simplestyle-spec, их сразу показывает geojson.io), остальные свойства — рядом. Запись и чтение без потерь
  - Чужие файлы: `name` вместо отсутствующего `title`, `properties.id` вместо отсутствующего `id`, `MultiPoint` — по точке на позицию, числа и прочие значения свойств — строками. Линии, полигоны и неверные координаты пропускаются с причиной в `GeoJsonReadResult.Skipped`
  - `IGeoDataContainerManager.ExportToGeoJsonAsync` и `SaveToGeoJsonFileAsync`; `LoadFromJsonAsync` и `LoadFromJsonFileAsync` узнают GeoJSON сами, пропуски попадают в `SkippedCount`. Ошибка экспорта не оставляет пустой файл
  - JS: `loadPointsOnMap` принимает GeoJSON по тем же правилам
  - Витрина: на `/map` точки можно скачать в GeoJSON и загрузить свой файл

- **Близкие точки 2D-карты сливаются в группы**
  - Маркеры, которые на текущем масштабе налезли бы друг на друга, становятся значком с числом точек; кольцо значка поделено между цветами точек, подсказка перечисляет первые восемь заголовков. Раньше Лондон на карте мира целиком прятался под Парижем
  - Клик по значку приближает карту ровно настолько, чтобы группа распалась (шагами колеса), а не до упора. Точки с одинаковыми координатами раскрываются веером — по кругу, а больше восьми по спирали Архимеда; клик мимо сворачивает веер
  - Группы считаются в пикселях масштаба и не зависят от сдвига: при перетаскивании не пересчитываются и не прыгают. На прямоугольной карте точки сливаются и через линию перемены даты. Точка под `focusOnParticipant` в группу не прячется
  - `CommunityMapComponent`: параметры `ClusterPoints` и `ClusterRadius` (меняются без пересоздания карты), настройки `Map:ClusterPoints` и `Map:ClusterRadius`; JS: опции `clustering` и `clusterRadius` у `initializeCommunityMap`, функция `setCommunityMapClustering`
  - Отпускание кнопки после перетаскивания карты больше не считается кликом по маркеру под указателем
  - Цвет точки из данных проверяется и в JS тем же шаблоном, что `GeoPointPalette.IsCssColor`

- **Карта и глобус показывают любые точки с цветами по категориям**
  - `CommunityMapComponent`: параметры `Points`, `DataContainerId` (карта обновляется вместе с контейнером), `CategoryColors`, `PointTemplate` (своя карточка точки), `OnPointClick`, `Title`, `ListTitle`, `ShowLegend`. Новые `Points` или `Participants` карта принимает без пересоздания
  - Легенда категорий над картой с числом точек; щелчок скрывает и показывает категорию на карте и в списке, не перекрашивая остальные
  - `GeoPointPalette` — общая логика цветов карты и глобуса: собственный цвет точки, затем `CategoryColors`, затем три автоматических цвета (синий, оранжевый, бирюзовый — различимы попарно при любом цветовосприятии на тёмной карте, проверено валидатором палитры), остальные категории — серые. Цвета из данных проверяются, прежде чем попасть в `style`
  - Маркер карты: короткая `Icon` или первая буква заголовка; подсказка и встроенная карточка показывают категорию, описание, свойства и ссылку (только `http`, `https`, `mailto`)
  - Глобус: `IThreeJsGlobeService.AddPointsAsync` и `IGlobeMediator.AddPointsAsync` раскрашивают маркеры по категориям; `CommunityGlobeViewer` читает из контейнера точки и принимает `CategoryColors`, `CommunityGlobeComponent` передаёт ему `DataContainerId` и `CategoryColors`
  - JS: `loadPointsOnMap`; `loadParticipantsOnMap` переводит участников в точки
  - Демо-наборы — точки с категориями и постоянными Id, без выдуманных email; витрина показывает легенду на `/map` и категории на `/globe`, набор данных на `/map` меняется без пересоздания карты

- **Контейнеры гео-данных хранят любые точки, а не только участников**
  - Модель `GeoPoint`: строковый `Id` (до 128 символов), координаты, `Title`, `Description`, `Category`, `Color`, `Icon`, `Url` и произвольные `Properties`. `Validate()` проверяет диапазон координат и длину полей, `Clone()` делает копию со своим словарём свойств
  - `IGeoDataContainer`: `AddPointAsync`, `AddPointsAsync`, `GetPointsAsync`, `GetPointAsync`, `UpdatePointAsync`, `RemovePointAsync`; `IGeoDataContainerManager.LoadPointsAsync`. Хранилища отдают копии точек, поэтому память и БД ведут себя одинаково
  - `GeoDataOperationResult.PointId` и `SkippedCount`: сколько записей пропущено при массовом добавлении
  - Участник хранится как точка: имя — `Title`, сообщение — `Description`, остальные поля — `Properties` (ключи в `ParticipantPointProperties`). Методы `AddParticipantAsync`, `GetAllParticipantsAsync`, `LoadDataAsync` и другие остались с теми же именами (теперь это методы-расширения), прежний код компилируется без изменений. `participant.ToGeoPoint()` и `point.ToParticipant()` переводят напрямую
  - `LoadFromJsonAsync` читает массив точек, массив участников в прежнем формате и их смесь; элементы без координат пропускаются

### Исправлено
- **Глобус вращался в пять раз быстрее задуманного.** `GlobeOptions.AutoRotateSpeed` по умолчанию был 0.5 рад/с (оборот за 13 секунд), а в скрипте и в `CommunityGlobeSettings` — 0.1. Теперь везде 0.1
- **`AutoGeocode` у `GeoDataParticipantForm` ничего не делал.** Таймер поиска создавался, но не запускался, поэтому «Место найдено» не показывалось. Теперь адрес ищется, как только поле адреса теряет фокус. Если адрес не найден, подсказка под полем говорит об этом ещё до отправки формы
- **Кэш геокодирования различал адреса по `GetHashCode()`**, поэтому два разных адреса с одинаковым хешем получали один ответ. Ключ кэша — сам адрес вместе с сервисом и языком
- **`GoogleMapsApiKey` был помечен как обязательный** (`[Required]` с сообщением только по-русски), хотя без ключа библиотека работает. Приложение, которое проверяет настройки через `ValidateDataAnnotations()`/`ValidateOnStart()`, без ключа не запускалось. Атрибут убран
- **Глобус без WebGL показывал пустую рамку.** Ошибка запуска оставалась внутри скрипта: `createGlobe` отвечал «создан», не дожидаясь `init`. Теперь он ждёт запуска и возвращает код причины
- **Геокодирование Google никогда не находило адрес.** Ответ API (`results`, `formatted_address`, `lat`/`lng`) разбирался без учёта имён полей, поэтому координаты не читались. Статус ответа теперь различает «адрес не найден» (`ZERO_RESULTS`), неверный ключ (`REQUEST_DENIED`) и временный сбой
- **Временный сбой геокодирования кэшировался на сутки.** Теперь кэшируются только найденные и ненайденные адреса
- Форма с `GlobeId` и `GlobeDataInitializer` при добавлении одной точки стирали с глобуса все остальные: `GlobeMediator.AddParticipantAsync` заменял набор. Теперь точка добавляется к показанным (`IThreeJsGlobeService.AddParticipantAsync`)
- Если один подписчик `OnDataChanged` бросал исключение (например, страница уже закрыта), остальные событие не получали. Теперь каждый подписчик вызывается отдельно
- Панель участников глобуса в `CommunityGlobeComponent` с контейнером записывала точку в общий репозиторий и заменяла на глобусе точки контейнера точками репозитория. Ещё она не проверяла, сохранилась ли точка

### Изменено
- **3D-глобус выглядит как планета, а не как серый шар.** Облака стали маской: белые облака, под ними чистая земля без серой пелены. Карта дня читается в sRGB, поэтому цвета больше не выцветшие. Вместо плоской сферы-кольца по краю шара светится атмосфера. На фоне звёзды. Солнце светит на 30° сбоку от камеры (`SunLightOffsetDegrees`), заливающий свет приглушён, поэтому у шара появился объём. Добавлена плёночная тональная кривая (ACES). Камера стоит так, чтобы шар занимал около трёх четвертей холста, а не половину. Значения `GlobeOptions` по умолчанию изменены под новый свет: `SunLightIntensity` 2.6, `AmbientLightIntensity` 0.3, `HemisphereLightIntensity` 0.25, `AtmosphereLightIntensity` 0, `AtmosphereOpacity` 0.7 (теперь это яркость свечения), `CloudsOpacity` 0.85 (плотность облаков), `CloudsSpeed` 0.01 (раньше 0.2, облака неслись слишком быстро)
- **Текстуры Земли.** Рельеф и блеск океана раньше не работали: их TIFF-файлы браузеры не открывают, но всё равно скачивали (около 11 МБ). Теперь это JPG 4K (`4k_earth_normal_map.jpg` и `4k_earth_roughness_map.jpg`). Карта дня 8K грузится только на компьютере, на телефоне и слабых видеокартах — 4K (`TextureQuality`). Облака — 4K в оттенках серого вместо цветной 8K (11 МБ → 2,4 МБ). `SpecularTextureUrl` устарел, вместо него `RoughnessTextureUrl`
- **Тише в консоли.** Компоненты и сервисы больше не пишут в `Console`: `CommunityGlobeViewer` пишет через `ILogger`, а записи о ходе обычных операций (загрузка точек, инициализация глобуса, работа контейнеров и репозитория) переведены с `Information` на `Debug`. Скрипты глобуса и 2D-карты печатают подробный журнал только при `globalThis.zealousGeoDebug = true`; предупреждения, ошибки и `debugGlobeState()` выводятся как раньше. Как включить журнал — в README, «Журнал»

- `GeoDataParticipantForm.Title`, `SubmitButtonText`, `CommunityMapComponent.Title` и `ListTitle` стали `string?`: без значения показывается перевод. Подпись списка карты по умолчанию — «Points» / «Точки» вместо «Members», счётчик без списка — «Points: N» вместо «Total Participants: N»

- **Email участника необязателен.** У `Participant` и `ParticipantRegistrationModel` нет `[Required]` у `Email`, а `ParticipantValidator` и `ParticipantRegistrationValidator` проверяют формат только у заполненного адреса (новый атрибут `OptionalEmailAddress`). Форма `GeoDataParticipantForm` подписывает поле «Email (optional)» и предупреждает, что указанный адрес виден всем на карте; пробелы по краям обрезаются

- **Демо-наборы (`DemoDataSets`) возвращают точки** (`List<GeoPoint>`) вместо участников
- Подсказка и карточка карты показывают поля участника как свойства точки; заголовок `Community Members (N)` внутри списка заменён кнопкой в шапке ещё раньше, счётчик в ней теперь считает видимые точки

- **Контейнеры гео-данных основаны на точках** (`GeoPoint`). Несовместимо для кода, который реализует `IGeoDataContainer` сам, обращается к `GeoDataDbContext.Participants` или к классу `GeoDataParticipantEntity` (теперь `Points` и `GeoPointEntity`). `ExportToJsonAsync` выгружает массив точек: поля участника лежат в `properties`. Участника без координат контейнер больше не принимает

- **Стили подключаются одной строкой `zealous-geo.css`**
  - Новый `wwwroot/css/zealous-geo.css` импортирует токены `zealous-ui.css` и стили всех компонентов
  - Компоненты больше не добавляют стили в `<head>` сами. Приложению нужно один раз подключить `<link rel="stylesheet" href="_content/ZealousMindedPeopleGeo/css/zealous-geo.css" />` в `App.razor` или `index.html`, после Bootstrap и до своих стилей
  - Хост витрины подключает этот файл вместо шести отдельных
  - Тест `experiments/library-stylesheet-bundle.test.mjs` проверяет, что в `zealous-geo.css` есть каждый файл стилей, компоненты не используют `<HeadContent>`, а файлы компонентов не переопределяют селекторы друг друга

- **2D-карта: единый масштаб по осям**
